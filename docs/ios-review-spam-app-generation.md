# iOS 심사 탈락: 게임 제작 앱이 유사 앱·생성 서비스로 분류됐다

게임을 만들고 실행하는 앱은 에뮬레이션이나 AI 채팅을 지원한다는 설명만으로 독자성이 전달되지 않을 수 있다. 같은 개발자 계정에 비슷한 제작 도구가 있으면, 실제 작업 흐름과 제품의 관계를 구체적으로 보여줘야 한다.

## 왜 탈락했나

2026년 10월 6일, Chip Toy의 **0.1.0(11)** 심사에서 **4.3(Spam)**과 **4.2.6(App Generation Services)**이 지적됐다. Apple은 기존 앱과의 중복, 충분히 구분되지 않는 기능, 콘텐츠 제공자 대신 제출된 템플릿 앱을 가능한 사유로 제시했다. 메시지에는 비교 대상으로 삼은 특정 앱이 적혀 있지 않았다.

Apple은 아래 아홉 항목에 대한 답변을 요구했다.

1. 앱이 하는 일과 사용자의 어떤 문제를 푸는가.
2. 구체적인 대상 사용자는 누구인가.
3. 기존 앱이 충분히 해결하지 못하는 필요는 무엇인가.
4. 어떤 베타 검증을 했고, 어떤 실제 피드백을 반영했는가.
5. 독립 제품인가, 같은 계정의 앱 묶음에 속하는가.
6. 다른 앱의 기능 확장이나 인앱 구매로 통합할 수 있는가.
7. 같은 계정의 다른 앱과 공유하는 코드·자산은 무엇인가.
8. 외부 앱·SDK·콘텐츠 라이브러리를 사용하며 무엇을 직접 추가했는가.
9. 고객·파트너 대신 제출한 앱인가, 실제 콘텐츠 제공자가 제출했는가.

이 거절 메시지는 로그인 실패를 지적한 것이 아니다. 별도로 발견했던 Apple 로그인 문제의 복구와 이 제품 분류 문제를 구분했다.

## 어떻게 보강했나

첫 실행 화면은 Game Boy 제작이라는 짧은 문구와 로그인 버튼만 보여줬고, 홈에는 공개 게임 목록이 있었다. 다음과 같이 제작 흐름을 앞에 드러냈다.

- 로그인 화면과 홈에서 원본 인터랙티브 튜토리얼을 바로 실행한다. 공유된 튜토리얼은 로그인 없이 플레이할 수 있다.
- Game Boy Color·Game Boy·NES 제작을 함께 설명한다.
- 새 프로젝트에서 앱 안의 Code Buddy와 자신의 연결된 AI 중 제작 방식을 선택한다. 선택한 채팅 또는 연결 설정으로 이어진다.
- 프로젝트 생성만으로 유료 AI 요청을 시작하지 않는다.
- 심사 메모에 생성 → 요청 → 플레이 → 기록 → 소스 확인 경로를 적는다. 스토어 설명도 현재 화면의 AI 정보 표시와 일치시킨다.

답변에서는 단순한 AI 채팅·에뮬레이션을 독점적인 발명처럼 주장하지 않았다. 인증된 MCP 도구, 격리된 서버의 ROM 빌드와 실행 화면 확인, 저장 버전, 공개 플레이 링크, 대응 게임의 온라인 플레이가 연결되는 작업 흐름을 설명했다. 생성물은 한 앱 안에서 사용하는 게임 콘텐츠이며, 고객별 네이티브 앱이나 App Store 등록물을 만드는 서비스가 아니다.

## 비슷한 자사 앱은 숨기지 않는다

이 사례에는 같은 계정의 NES Club과 NES 제작 기능이 겹친다. NES Club은 편집 가능한 NES 전용 브라우저 제작 도구이며, Chip Toy는 서버 빌드·MCP·GB/GBC·공유 릴리스·온라인 플레이를 중심으로 설계됐다. 개발자는 NES Club 개발을 중지할 예정이고 향후 제작 기능 개발을 Chip Toy로 이어가겠다고 확인했다. 기존 앱이 이미 철회됐거나 데이터가 이관됐다고 적지 않는다.

Mono & Watch는 Lua 기반 판타지 콘솔의 게임 모음으로 구분했다. 공유하는 Capacitor 등 표준 구성요소와 NES Club에서도 사용하는 romdev NES 런타임·cc65를 명시하고, 직접 구현한 프로젝트·버전·MCP·백그라운드 실행·멀티플레이 계층을 설명했다. 외부 컴파일러·에뮬레이터의 출처와 라이선스 안내도 남긴다.

## 검증과 제출 상태

제한된 내부 TestFlight 검증에서 개발자가 Apple 가입 팝업 실패를 보고했고, 설정 복구 후 실제 로그인 성공을 확인했다. Apple 버튼을 Google 위에 배치해 달라는 피드백도 빌드 12부터 반영했다. 외부 사용자 연구나 대규모 베타가 있었던 것처럼 적지 않는다.

보강된 화면은 390×844에서 렌더링하고 두 제작 방식의 이동을 확인했다. 빌드와 **349개 자동 테스트**가 통과했다. 실제 서비스의 튜토리얼에서 A 입력으로 페이지가 바뀌는 것도 확인했다. 자동 테스트와 화면용 가짜 응답은 실기기 인증 또는 사용자 베타 피드백을 대신하지 않는다.

2026년 10월 6일 **0.1.0(12)**로 다시 제출했고, 앱·크레딧 3개·구독 그룹·구독 3개, 총 **8개 항목이 심사 대기 중**인 것을 App Store Connect 화면과 API에서 확인했다. Apple의 아홉 질문에 대한 답변과 NES Club 개발 중지 계획을 회신하고, 심사 메모와 설명을 갱신했다. 보강은 [PR #190](https://github.com/ssk-play/chiptoy/pull/190)으로 머지한 뒤 개발·운영 웹서비스에 배포했다. **최종 승인은 아직 확인되지 않았다.**

## 다음에 확인할 점

비슷한 앱을 같은 계정으로 운영한다면 차이뿐 아니라 통합·종료 계획도 설명한다. 공유 코드가 있으면 범위와 역할을 밝히고, 확인된 베타 피드백만 기록한다. 첫 화면과 심사 경로는 실제 핵심 기능을 바로 발견할 수 있어야 한다.

관련 기준은 [Apple의 4.3](https://developer.apple.com/app-store/review/guidelines/#spam)과 [4.2.6](https://developer.apple.com/app-store/review/guidelines/#minimum-functionality)을 참고한다. 샘플의 권리와 테스트 파일 준비는 [ROM 심사 메모](./ios-review-rom-rights-and-sample.md)에 따로 정리했다.
